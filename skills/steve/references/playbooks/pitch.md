# Playbook: pitch

**Question:** How would he say it? The headline, the one-liner, the name, the keynote.
**Use for:** a README first screen, a landing page hero, a tagline, a product name, a launch post, a Show HN title, a demo script, an investor one-liner, "I can't explain what my app does".

His positioning lines: "1,000 songs in your pocket" (iPod, 2001); "an iPod, a phone, and an internet communicator" (iPhone, 2007); "the world's thinnest notebook" (MacBook Air, 2008). The pattern: one concrete number or image a person can picture, a comparison to something they already know, the benefit in the sentence itself, nothing about how it works.

The keynote structure he used every time: name the problem or the villain; the headline in under ten words; three things, never four; numbers made human; show it working; one more thing, only when there is one.

## Steps

1. **Get the one thing.** If the user has not stated it, derive it — the first three steps of `why.md` are enough. Everything below is that sentence, dressed.
2. **Write five headlines, show three.** Under ten words each. Write five for yourself: at least two with a number or an image, one that names the enemy, one that compares to something familiar. Then show the winner and the two closest runners-up, each with one line on why it lost. The runners-up are where the user sees the thinking; do not skip them and do not show all five.
3. **The three things.** Three, always three. Each is a benefit a person can picture, not a feature name.
4. **The demo moment.** The single thing you would show first, and what the room says out loud when they see it. If nothing makes them say anything, the product is not ready for a pitch; say that instead.
5. **Rewrite theirs.** Take their actual copy — tagline, README first screen, hero section — and show before and after. Name what you deliberately left out of the sentence (the architecture, the protocol, the framework list) and where it should live instead.
6. **Check the name.** If the name describes the wrong thing, fights the pitch, or makes a stranger picture a different product, say so. For anyone who cannot explain their product, the name is a live suspect about half the time. Skip the slot when the name is fine.
7. **One more thing.** Only when there is a real surprise. Never a recap.

## Template

```
**Mode:** pitch · <subject>

**The one thing.** "<one sentence — the need, not the headline>"

**Headline.** <the winner, under ten words>
Runners-up: <two, one line each, why they lost>

**Three things.**
1. <benefit you can picture>
2. <benefit>
3. <benefit>

**The villain.** <only if neither the headline nor the demo moment carries it>

**The demo moment.** <what you show first> → the room says: "<...>"

**Before → after.**
Before: "<their current copy>"
After: "<the rewrite>"

**The name.** <only if the name is a problem>

**One more thing.** <only if there is a real surprise. Never a recap.>

*(one italic line if a call above is taste rather than measurement, or if their own data should overrule it)*
**What Steve would say.** *(imagined)* "<one line>"
```

## Traps

- Adjectives. "Powerful, flexible, seamless" are not a pitch. A number is. An image is.
- Four things. Three.
- Explaining how it works. Nobody buys the how. CRDTs, Rust, the event bus: second paragraph, for the engineer already leaning in.
- A "one thing" that is just the headline again. The one thing is the human need; the headline is how you sell it.
- Names that describe. "SmartTaskManager" is a description. Short, sayable, ownable.
- Copy only the builder understands. Read it as the stranger.

At most one real sourced quote in the reply, and only when it does work no sentence of yours does. It may sit under the closer.
