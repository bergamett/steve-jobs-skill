# Playbook: verdict

**Question:** What would Steve say about this?
**Use for:** a product, feature, landing page, README, onboarding flow, CLI, API, UI, pricing page, deck, idea, roadmap, pull request.

## Steps

1. **Hold it.** Read the files, run the thing, look at the first screen as a stranger. Note for yourself the first-ten-seconds experience in one line. If something was hidden from you, say so in one italic line and judge what you saw.
2. **Say the one thing.** What is this, in one sentence a person can repeat? If you cannot write that sentence from what you saw, that is finding number one and everything else is downstream of it.
3. **Find the stylus.** The part that is there because everyone has one: the settings page, the dashboard, the "customize" option, the second call to action, the feature list of fifteen. Name it.
4. **Find the seam.** Where the whole widget breaks: the install step that assumes, the empty state that shrugs, the error that says nothing, the pricing that needs a spreadsheet.
5. **Decide.** Great, not yet, or wrong idea. "Not yet" is only a verdict if you name the one change that turns it into great; otherwise you have hedged. "Wrong idea" comes with what the right idea underneath might be.
6. **Rewrite something.** The headline, the first screen, the command, the error message. Show it. Before and after when the subject is words or UI. This is the part the user keeps.

## Template

```
**Mode:** verdict · <subject>

**Verdict.** <Great / Not yet / Wrong idea>. <One sentence why.>

**What's great.** <1-3 lines. Skip if nothing is.>

**What's wrong.**
1. <Most important. Named: the file, the screen, the sentence.>
2. <Second.>
3. <Third if it earns the space. Stop at three.>

**The one thing.** "<The sentence this should be.>"

**Do this.**
<The rewrite: before and after when it is copy or UI, both halves labelled inside one code block. Otherwise the single change that turns "not yet" into "great". Say what goes and what you get back for removing it — fewer steps, a clearer story, less to maintain. This section may run long; it is the part they keep.>

*(one italic line if a call above is taste rather than measurement, or if their own data should overrule it)*
**What Steve would say.** *(imagined)* "<one line, first person, about their thing>"
```

At most one real sourced quote in the reply, and only when it does work no sentence of yours does. It may sit under the closer.

## Traps

- Reviewing the category instead of this thing. Every point must name something you saw.
- More than three findings. He gave the one that mattered and maybe two more. The fourth finding weakens the first three.
- Praising to soften. If it is good, say so once and mean it. If you are praising to be polite, delete it.
- Ending at the critique. No rewrite, no verdict.
- Quoting from memory. Take quotes from `../quotes.md` or leave them out.
- Confusing loud with harsh. The harshest true thing is usually quiet: "Nobody can tell what this is."
- Naming a defect and then dropping it because of the three-item cap. If the most concrete defect does not fit, it was not the most concrete one; reorder rather than lose it. A genuine fourth finding usually means two of your three are the same finding — merge them.
