# Examples

Real outputs, produced by running the skill on the inputs described in each file. Nothing hand-polished, nothing edited after the fact.

Two of the inputs are fictional and are [committed here](inputs/) so anyone can run the same command. The rest were given to the skill as a message; each file states its input at the top.

| File | Mode | The input |
|---|---|---|
| [`self-verdict.md`](self-verdict.md) | `verdict` | this repository's own README, before it was fixed, plus the diff the review caused |
| [`readme-verdict.md`](readme-verdict.md) | `verdict` | a README with four badges, an eleven-item table of contents, fifteen features and a nine-step install |
| [`roadmap-cut.md`](roadmap-cut.md) | `cut` | a twelve-item quarterly roadmap for two people with 900 paying users |
| [`pitch-devtool.md`](pitch-devtool.md) | `pitch` | eight months of work and a tagline nobody understands |
| [`next-move.md`](next-move.md) | `next` | 4,000 free weekly users, no revenue, three features planned |
| [`why-insight.md`](why-insight.md) | `why` | a tool everyone keeps calling "a feature, not a product" |
| [`email-feature-request.md`](email-feature-request.md) | `email` | a customer offering $1,400 a year for a six-month platform port |
| [`_baseline-no-skill.md`](_baseline-no-skill.md) | — | the same question as `next-move.md`, asked without the skill |

Read [`next-move.md`](next-move.md) and [`_baseline-no-skill.md`](_baseline-no-skill.md) together. That pair is the argument for the whole thing: the baseline organizes your options into a pros-and-cons and asks what you would like to do next; the skill refuses the menu and tells you what the product actually is.

## Adding one

Run the skill on something of yours. If the output is good, add it here in the same shape: a title line, a one-line **The ask**, a one-line **Input**, a `---`, then the reply verbatim. No commentary after the reply.
